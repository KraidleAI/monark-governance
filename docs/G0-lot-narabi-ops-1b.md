## Faits mesurés (relecture first-hand du code + ADR + décisions, 2026-09-20)
1. **[lu, code]** La surface publiée par le sentinel est **exactement deux fichiers** : `run.ts:186-191` écrit `timeline.jsonl` (append) et `state.json`, puis les **copie** dans `public/` (servi par Caddy `handle_path /narabi/*`, `deploy/Caddyfile.monark-narabi.snippet`, confirmé `test/narabi-live.test.ts:164-189`) — URL `https://monarkgate.tech/narabi/{timeline.jsonl,state.json}` (`RUNBOOK-sentinel.md:118`). **Ni `chainstack` ni `exit_code` ne figurent dans ces fichiers** : ils ne vivent que dans le JSON de fin sur **stdout / journalctl** (`run.ts:180`), invisible de l'extérieur. Conséquence directe : la sonde externe **ne peut lire ces deux champs tels quels** ; elle doit les inférer de la surface servie (voir faits 2-3) ou exiger un fichier de santé publié (Q1, hors L-n par défaut).
2. **[lu, code] `exit_code` du run PUBLIANT a un proxy externe exact.** `run.ts:175` : `exitCode = report.stopped !== null ? 1 : 0` ; table `ADR-NARABI-OPS-1.md:63-73` : `exit_code = 1` **⟺** `stopped != null` **⟺** un jour dû non rattrapé. Donc **une ligne J−1 fraîche et chaînée implique que le run qui l'a ÉCRITE a fini `exit_code = 0`** (un `stopped != null` n'écrit jamais la ligne du jour fautif — `run.ts:182` n'écrit que si `report.lines.length > 0`). **Portée exacte** : la fraîcheur J−1 prouve le code du **run publiant**, pas de chaque créneau. Un créneau de retry peut `FATAL` **avant** le JSON de fin (`run.ts:201` : `finalized()` sans quorum lève, `process.exitCode = 1`, **rien d'écrit, aucune trace externe**) ; c'est **bénin** quand J−1 est déjà publié (retries no-op) et **capté** par la fraîcheur quand J−1 manque encore. Le seul cas invisible sans `health.json` = un créneau qui FATAL alors que le jour est déjà sain (non-incident) ⇒ renforce le report de `health.json` (Q1 : indicateur avancé, non bloquant). **→ Amend. C-9** : la fraîcheur J−1 sur la surface **publiée** (`public/`) prouve `exit_code 0` du run publiant **sauf** crash entre `run.ts:188` (append privé) et `:190-191` (copies publiques) — la sonde voit alors un lag et alerte, **ce qui est correct** (la publication a échoué) ; jamais un faux négatif.
