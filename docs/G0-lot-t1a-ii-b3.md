## Objectif (une phrase)
Rendre calculable `multiplier(mint, t)` pour tout instant t passé de la fenêtre Solana (2025-07-01 → 2025-10-31, puis extension 2025-11 → 2026-09) par rejeu chronologique des instructions `UpdateMultiplier` (Token-2022, discriminants 43/1) sous quorum-2, afin que le gate `rebase` sorte `constant` ou `trajectory_known` au lieu de `rebase_unverified`, et que -b1-bis puisse calculer la g_t fondatrice avec le bon multiplicateur à chaque fill.

## Faits [lu] qui fixent la méthode (lecture 2026-09-20)
1. Règle : `current_multiplier(t) = new_multiplier si t >= new_multiplier_effective_timestamp sinon multiplier` ; `UpdateMultiplier` écrase inconditionnellement `new_multiplier`/`effective_timestamp` et replie `multiplier` immédiatement si `clock >= effective_timestamp` ; un second appel avant l'échéance du premier efface le premier ⇒ **rejeu des instructions, jamais snapshot**.
2. `getAccountInfo` à un slot passé : impossible en RPC standard ; Alchemy account-archive (`slot`) existe, palier non confirmé ; Chainstack/Helius muets ⇒ ne pas en dépendre ; item formé si l'accès est confirmé (contrôle croisé, pas source).
3. Scan **par mint** (`getSignaturesForAddress(mint)` paginé 1000, `before`/`until`) puis `getTransaction(sig, {maxSupportedTransactionVersion: 1})` ; filtre client `data[0]==43 && data[1]==1` ; coût = N signatures totales du mint (8000+ par mint xStocks in-window, mesuré -b1).
4. f64 LE ; ordre des champs instruction ≠ état ; deux décodeurs.
