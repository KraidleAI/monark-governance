- **Status**: accepted (G1 worker), pending G2 / checkpoint-2 / G7.
- **Date**: 2026-09-20.
- **Provenance**: generated by worker implementer G1, model pinned `claude-opus-4-8` (effort max); orchestrator

## Context

On 2026-09-20 the 00:44 UTC sentinel run stopped on `no_quorum` (publicnode HTTP 403 while too few of the 8
free endpoints answered): `stopped != null`, `lag: 1`, `processedDays: []` — **and it exited 0**. Because the
unit is a `Type=oneshot`, `Restart=on-failure` would not have fired even if set (nothing failed, per the exit
code), so 2026-09-19 stayed unpublished for ~4 h until a manual relaunch at 04:58 UTC. The window's data was
identical on relaunch (archive blocks); only the delay changed (ADR-M012 D5: "a missed day is LAG, never a
skipped step"). Three causes compound: (a) a oneshot that exits 0 on a stopped day is invisible to systemd and
to any probe reading only the exit status; (b) the free pool has no paid, reliable operator; (c) nothing off
the VPS notices a stalled publication.

## Decisions

- **D1 — exit code carries the stop (L-1).** `run.ts` exits **1** iff `report.stopped !== null` (a fetch /
  quorum / c1 / unfinalized failure prevented catch-up), **0** otherwise (up to date, or waiting for finality
  — `due` empty or fully processed). The end JSON gains `exit_code`. Lines processed BEFORE a stop are written
  first; the non-zero exit is set after (partial catch-up is preserved, never rolled back). `runDue` sets
  `stopped` only with `lag >= 1`, so the plan's `lag > 0` is implied by `stopped !== null`.

- **D2 — the retry is four timer slots, not systemd `Restart=` (L-2).** `monark-sentinel.timer` fires at
  `00:30`, `03:30`, `06:30`, `09:30` UTC (four separate `OnCalendar=` lines — the single-line comma list
  `00:30,03:30,…` is an INVALID spec, C-2), `RandomizedDelaySec=1800`, `Persistent=true` (one boot catch-up,
  never one per missed slot). By 00:30 the previous UTC day's close is finalized, so the first slot publishes;
  a transient failure is caught up by a later slot the SAME day. Once the line is written, each later slot is a
  no-op "nothing due" — idempotent, proven offline by the L-4 replay. The service stays `Type=oneshot` (a clean
  journal); the retry lives in the timer, not in `Restart=`.

- **D3 — a keyed third operator, its URL out of the repo (L-3 / C-3 / C-4 / C-5).** When
  `CHAINSTACK_ETH_URL` is set, the pool gains it as a **ninth endpoint and a distinct operator** (`providerOf`
  → `chainstack.com`, not among the 8 free providers) in the round-robin rotation — no ordering privilege is
  claimed (`quorumTwo` rotates `rr`). `providerOf` is left **byte-identical** (imported under contract by Bell
  `operators.ts`/`quorum.ts` and `ukemi/rpc2.ts`); the sentinel holds only ONE Chainstack URL, so no p2pify
  merge is needed here. The URL is read ONLY in `main()` (via `poolEndpoints(env)`), never at module scope nor
  in `makeRpcPool` defaults, so the injected-`endpoints` test path never consults the env. The end JSON gains
  `chainstack: boolean` for visibility (a silently key-less run is diagnosable). The key lives in
  `EnvironmentFile=-/etc/monark/sentinel.env` (`root:sentinel 0640`, never committed); the leading `-` makes it
  optional — absent, the base 8-endpoint pool stays fail-closed and keeps publishing.

- **D4 — the endpoint URL is never printed (C-1, bloquant).** `run.ts:160` publishes `prov.endpoints` in every
  served line (`narabi-snapshot.ts`), so a raw Chainstack URL would put the key ON THE SITE. Fix: the 8 public
  URLs are published **verbatim** (`PUBLIC_ENDPOINTS` unchanged); the Chainstack endpoint is published
  **redacted to its origin** (`redactEndpoint` → scheme + host, never path/query — `publishedEndpoints`). Every
  error carrying a URL is reduced to `HTTP <status> <origin>` (`defaultCall`). `endpoints` is outside
  `hashedFields`, so redaction does not touch `line_hash`. `sentinel_never_prints_endpoint_url` asserts on the
  **error**, the **written line**, and **stdout**; the mutant "raw URL" reds each.

## Amendment to ADR-M012 D5 (dated reference)

ADR-M012 D5 ("pool RPC public, sans clé") is amended **2026-09-20** by ADR-NARABI-OPS-1: the pool MAY carry one
keyed operator (Chainstack) whose URL lives OUTSIDE the repo (`/etc/monark/sentinel.env`, `root:sentinel
0640`); the keyless base pool remains fail-closed and continues to publish without it. D5's fail-closed quorum
(two distinct providers) is unchanged; the key only ADDS a ninth operator.

## Exit-code semantics (D1)

| `report.stopped` | meaning | `exit_code` | lines written |
|---|---|---|---|
| `null`, `due != []`, all processed | caught up | 0 | N >= 1 |
| `null`, `due == []` | up to date, or waiting for finality | 0 | 0 |
| `fetch_error:D:...` | RPC / quorum failure at day D | 1 | days before D (partial) |
| `quorum_disagreement:D` | two endpoints disagreed (fail-closed) | 1 | days before D |
| `unfinalized_to_block:D` | belt: `to_block > finalized` | 1 | days before D |
| `c1_fail:D` | C1 identity broke (fail-closed) | 1 | days before D |
| `--dry-run` (any of the above) | inspect only — same stop/exit semantics, nothing written | 0 or 1 (mirrors the run) | 0 |

## Deferral of L-5 (C-11, R-25)

Measured at G1 (mid-lot, `git diff --shortstat eac7eea` under the ci.yml R-25 pathspec, untracked files
included via `git add -N`): the core (L-1..L-4, L-6) is **423** changed lines (398 insertions + 25
deletions; the 424 milestone dropped one line in the lint clean-up). The probe (L-5:
`scripts/probe-narabi.mjs` + `scripts/probe-narabi.d.mts` + `deploy/monark-probe.{service,timer}` +
`test/probe-narabi.test.ts`, ~200 lines) would push the lot to ~620, over the 500 target. Per C-11, **L-5
becomes pli NARABI-OPS-1b** (a formed item, not a dropped one). Full spec for 1b (a pickup, not a re-plan):
`scripts/probe-narabi.mjs` uses Node built-ins only (no `@monark/*` — `line_hash` is not importable on the Bell
VPS), **duplicates the 31-field `hashedFields` order** and recomputes `line_hash` = `sha256(JSON.stringify(the
31 fields))`; it GETs `/narabi/timeline.jsonl`, checks last `day == J-1` (after 10:00 UTC), `prev_line_hash`
continuity, and the recomputed last `line_hash`, writes `{ok,last_day,lag_days,checked_at}` to
`/var/lib/monark-probe/narabi.json`, and **exits 1 if `lag_days > 0`**. It injects `--file`/`--now` (or env) for
offline tests. `test/probe-narabi.test.ts` (root — NOT under `apps/sentinel/test`, which is exported
package-style and would crash the public CI on the missing `.mjs` import) with a `scripts/probe-narabi.d.mts`
sidecar (TS7016): `probe_line_hash_equals_sentinel_lineHashOf` (probe hash == `timeline.ts` `lineHashOf` on the
committed lines — the C-7 fixture and `narabi-snapshot.ts`) and `probe_narabi_detects_lag` (J-2 ⇒ exit 1; J-1 ⇒
exit 0; J-1 with one hashed field tampered ⇒ exit 1 — the "recompute skipped" mutant). `deploy/monark-probe.
{service,timer}` on the **Bell VPS** (distinct host = external), user `probe`, `ReadWritePaths=/var/lib/monark-
probe`, `OnCalendar` **≥ 10:30 UTC** (past the last slot's jitter). Open item: whether `monark-probe.*` join
`vocab-banned.json` `scan.sentinel.files` (a governance line) or stay a formed item — resolve in 1b.

## Risks (MAST)

- **Secret in the published provenance** (the C-1 leak vector) — counter: `publishedEndpoints` redacts to
  origin; `sentinel_never_prints_endpoint_url` asserts error + line + stdout; `no_secret_in_repo` scans the
  Chainstack/p2pify/wss shapes in the committed tree.
- **Retry rewrites a line** — counter: L-4 idempotence (run 3 = "nothing due", 0 new lines; mutant M7 partial-
  write-skip reds).
- **A key in a log** — counter: `defaultCall` error carries the origin only.
- **Silent key-less degradation** (EnvironmentFile absent ⇒ back to the free pool that caused the incident) —
  accepted over "refuse to start" (a unit that will not start publishes nothing, with no alert channel yet, a
  worse failure); made visible by `chainstack: boolean` and the RUNBOOK `systemctl show -p EnvironmentFiles`.
- **Duplicated hash-order drift in the probe** — deferred with the probe (pli 1b); countered there by
  `probe_line_hash_equals_sentinel_lineHashOf`.
- **Four RPC reads/day** — cost: three no-op runs = two `finalized` reads each, negligible.

No gate is suspended (R-22). CA-11: nothing new is declared built (`fleet.ts` intact — Narabi was already built
at go 4); the probe is an operations tool, `upcoming` with a declared pipe + trigger.
