Sans C-3, le critère d'acceptation 1 (« `npm run ci` = base + 4 tests ») est faux.
- **C-4 (R-25)** : remplacer « ≤ 400 » par la gate réelle **1 205** (`VIBEGATES_PR_LIMIT`, ADR-M003 D9) avec estimation honnête (script env. 400-450, 4 tests env. 200 ; `U3-inputs` exclu par C-2 ; `.md` exclus par D9 septies) ; consigner la récurrence (ADR-U1 D9 avait déjà corrigé « 400 ») — `error_origin` planificateur.
- **C-5 (définition des événements, pré-engagée dans L-1)** : pour chaque e : cluster (filtre collatéral exact : e1 = sUSDe/USDe, e2 = **WETH**, e3 = sUSDe/USDe), `B_first` = premier `LiquidationCall` du cluster, `B_last` = `firstBlockAtOrAfter(ts(B_first)+86400) - 1` (24 h, classe M020 D1 (b) ; `windows.ts` ne fournit que le jour UTC — l'écrire), **n attendu** (appels **et** positions) : e1 = 5 / 3 ; e2 env. 239 / 189 (exact à fixer au prereg) ; e3 = 1 / 1 ; appels du cluster hors fenêtre comptés en résidu `outside_window` (e2 env. 29). Position = `(user, debtAsset, collateralAsset)`. Dunn (L-4) se lit sur les **positions**.
- **C-6 (implémentation déployée, pas `main`)** : le prereg résout l'implémentation du Pool à `B_first` de chaque événement (log `Upgraded` `0xbc7cd75a...` sur le proxy `0x87870Bca...`, quorum-2) et la release taguée correspondante ; e1 est **pré-v3.3 par construction** ⇒ `deficit_topic_absent` ; U3-H1 devient « `DeficitCreated` apparaît dans ≥ 1 des **2** événements post-v3.3 ». Le worker vérifie sur **un receipt par événement** (Blockscout keyless, motif census A §8) la sémantique de C-7 avant de généraliser.
- **C-7 (cross-checks sur les bons `Transfer`)** : les `Transfer` des tokens scaled sont **nets de `balanceIncrease`** (V-8) ⇒ jamais égaux à l'unité. Croiser sur les **underlying ERC-20** : `repayment` ⇔ `Transfer(liquidator -> aToken(debtReserve), actualDebtToLiquidate)` sur le contrat du debtAsset ; `seized` ⇔ `Transfer(aToken(collateral) -> liquidator, actualCollateralToLiquidate)` sur le contrat du collatéral quand `receiveAToken=false` (tous les cas sUSDe mesurés) ; `receiveAToken=true` ⇒ `BalanceTransfer` aToken, déclaré. Déclarer que `seized` **exclut le frais protocole** (treasury) ; le frais peut être enregistré à part. Tout écart = ligne `residual: xfer_mismatch`, jamais tolérance muette.
- **C-8 (déficit : clé et contrôle positif)** : `U3-deficit.jsonl` clé `(user, debtAsset, block, tx, amount)` ; `deficit_base` d'une ligne position = déficit du **même debtAsset dans la même tx** ; déficits d'autres réserves (`_burnBadDebt`) en lignes `bad_debt_other_reserve` rattachées au `user`, **pas** à un collatéral. **Contrôle positif** obligatoire : au moins 1 `DeficitCreated` réel trouvé on-chain après l'upgrade (n'importe quel bloc, quorum-2) prouvant que le filtre attrape ; sinon « déficit = 0 » n'est pas falsifiable. Mutant : topic altéré ⇒ contrôle positif rouge.
- **C-9 (prix et base)** : `BASE_CURRENCY_UNIT()` **lu on-chain** (quorum-2), jamais « 1e8 » codé ; `getAssetPrice` au bloc b = état **post-bloc** — hypothèse déclarée « aucune mise à jour d'oracle après la liquidation dans le même bloc » (M-2b §4.2 : update précède 15/15, 0 multi-log) + résidu `price_moved_in_block` (P au bloc b différent de P au bloc b-1) compté, non corrigé. `partial_liquidation` **opérationnalisé** : `balanceOf(debtToken)` (ou `getUserAccountData`) à `B_last` par position, quorum-2, **compté** dans `--max-calls` (env. 2 x n_positions appels, L-2).
- **C-10 (pré-enregistrement imposé par le système)** : « ordre des commits » ne prouve rien puisque le pull est hors dépôt. Mécanisme : L-1 committé **seul** (hash cité) ; le script refuse de démarrer sans `--prereg-sha` égal au sha LF de `PLAN-u3-prereg.md` et l'écrit dans le manifeste des bruts et dans `U3-inputs.jsonl` ; `PROVENANCE-u3.md` cite hash de commit + sha. U3-H3 devient une **identité de pipeline** (somme repayment par (e, debtAsset) en unités natives = somme `debtToCover` des lignes retenues de `A-rawlogs`), pré-engagée en chiffres : e1 USDC 8 511 568 493 136 + USDT 12 871 019 904 705 ; e3 USDC 3 322 388 532 587 ; e2 à fixer au prereg. « Bissection » de source = contrôle aux **deux bornes** (`B_first-1`, `B_last`) ; bissection seulement si différence (U3-H2).
- **C-11 (MAST + tuyau)** : tableau mode → contre-mesure (fixture auto-enregistrée ⇒ G2 re-tire au moins 3 lignes live quorum-2 indépendamment de `U3-inputs` ; prix moyen ⇒ test « prix par bloc distinct » ; fenêtre horodatée ⇒ grep) ; ADR-U3 nomme le **test** d'intégration du tuyau consommé par U-4 (nom réservé, écrit en U-4).
