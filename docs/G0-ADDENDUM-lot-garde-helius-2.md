## Décisions de conception
- **D1 — tarif `chainstackRu(method)` CONSERVATEUR fail-closed** dans `packages/rpc-guard/src/tariff.ts` : 2 RU pour toute méthode des listes fermées du fait 4 (20 EVM sensibles à l'âge + `debug_*`/`trace_*`/`arbtrace_*`/`eth_callMany` + 8 Solana archivables), 1 RU pour les autres, **méthode inconnue du tarif ⇒ refus `unknown_method`** (calque Helius). Motif : le garde ne connaît pas le tip hors ligne ; le sur-compte est sûr (le rapprochement est asymétrique `Δdashboard ≤ ledger_run`, décision 113) ; jamais un sous-compte. `CHAINSTACK_TARIFF_VERSION` daté 2026-09-21, source = FAITS.
- **D2 — second opérateur payant dans `transport.ts`** : label `chainstack`, classe `requests`→`ru`, `cycleCap = CHAINSTACK_CYCLE_CAP_RU` (16 000 000), clé lue de `CHAINSTACK_ETH_URL` **dans `transport.ts` seulement** ; `apps/sentinel/src/rpc.ts:50-54` cesse de lire la clé pour le chemin recorder (voir D4 pour le job quotidien).
- **D3 — corrections du cœur portées par ce lot (fait 5)** : prior par opérateur (déjà structurel depuis le ledger par opérateur — prouvé par un test à DEUX opérateurs payants aux unités distinctes) ; acquisition multi-verrou **atomique avec rollback** (échec du k-ième ⇒ relâche des k−1 précédents, 0 transport) ; **prior figé APRÈS le verrou** (ouvrir/relire le ledger sous verrou). Mutants : rollback retiré ⇒ rouge ; prior lu avant verrou ⇒ rouge (test bi-processus : un writer encore verrouillé appende entre la lecture et l'acquisition ⇒ le second voit le prior à jour ou est refusé).
- **D4 — périmètre de migration** : (i) **recorder Ukemi** (`record.ts`) : `makeBudgetedCall` local SUPPRIMÉ ; `runRecorder` construit `openGuardedClient(env, limits, ledgerDir, cycleId)` ; nouveaux arguments REQUIS `--ledger-dir`, `--cycle`, `--max-ru` (cap de run en RU), `--method-caps` (fail-closed par méthode) ; `--max-calls` conservé comme cap de run en appels ; les opérateurs gratuits passent par le même client (classe `keyless`, coût 0, comptés). (ii) **job quotidien sentinel** (`run.ts` → `rpc.ts:125`) : **HORS de ce lot** (production, E-5, lot `run.ts` à venir) — déclaré : `rpc.ts` garde sa lecture de clé pour ce seul chemin, inscrit à l'allowlist du grep CI **avec déclencheur « lot run.ts/E-5 »**, jamais une allowlist silencieuse. (iii) **U-4b-0 subsumé** : le discover/calib de U-4b-1b consommera ce recorder gardé ; aucun second compteur.
- **D5 — identité d'erreur** : `BudgetExceededError` de `record.ts` devient le ré-export canonique du paquet (G0 §2.3) ; `withRetry` du recorder ne ré-essaie JAMAIS une `BudgetExceededError` (mutant « retry avale le refus » ⇒ rouge) ; une seule couche de retry, chez l'appelant (G0 §2.2).
