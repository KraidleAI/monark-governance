**Contract of `riskControlQuantile`**. Returns `{ qhat, rank, kStar, kObs, missBound }` or `{ reason: "under_calib" }` (no `qhat` key). kStar = `riskControlMaxExceedances(n, alpha, delta)` (exact big-integer comparator of `binomial.ts`); rank = n - kStar; qhat = the rank-th smallest score (ascending comparison sort; with ties, the order statistic at that rank); kObs = the count of scores strictly above qhat (descriptive, kObs <= kStar); missBound = `missUpperBound(n, kStar, delta)` (7 decimals rounded up), never computed from kObs. `under_calib` when: nMin is not a safe integer or n < nMin; a score is NaN; alpha or test_delta is refused by `parseAlpha` / `parseTestDelta` (not a plain decimal in (0, 1), alpha with more than four decimals, test_delta >= 0.25); n < n0 = `zeroErrorFloor(alpha, delta)` (the empty sequence included). Pure: no clock, no file, no floating point in a decision.

## 5. Declared deviations from the worksite G0 v3.1

- D-1: categories. P-1 to P-6 are F2P (red by assertion), not new-module, because `l1-split.ts` exists at every base (section 2).
- D-2: killers. P-2's intent "kStar loop overshoot by one" is expressed at the served rank (`n - kStar - 1`), the loop being L2-1 code already killed by B-3; P-3's intent "comparison `<=` -> `<` on the count" is expressed on the only count of this function (`s > qhat`); P-4's split-formula mutant is written as the float split formula on the rank line.
- D-3: file list. The worksite G0 lists `l1-split.ts` and the test for L2-2; this part adds the two L1 export lines of `index.ts` (L2-3 reads the function from the package entry) and the test support module `served-scores.ts` (the served arrays once instead of twice).
- D-4: the runs level parser (debt D-2 of L2-1r) is replaced by `parseUnitDecimal`: the same accepted set ("0." followed by one or more digits, not all zero), the same `RangeError` class and the same decision (the ratio is reduced; the comparison tailNum x den <= num x tailDen is scale-free); only the error message text differs ("not a plain decimal in (0, 1)" instead of "runs: level must be ..."), which no test or consumer reads.
- D-5: guards beyond the list of the worksite G0 (n < nMin, n < n0, bad input): a NaN score and a nMin that is not an integer also give `under_calib`; an unreachable rank outside 1..n throws a `RangeError` (it can only be reached by a code change; the tests' helper turns such a throw into an assertion failure, which is how the P-5 killer is killed).
- D-6: the worksite G0 v3.1 is cited at sha256 `ed89085b...` (the L2-1r2 lot G0 cites `c5b6183a...`, an earlier revision of the same v3.1 file).
- D-7: P-3 is named `risk_control_rank_indicator_singleton_iff_errors_at_most_kstar`: the worksite G0 name ends in `_errors_le_kstar`, whose `le` token is a French word for `lang:gate` (hikae scope), which the byte rules of the worksite G0 section 7 forbid even inside snake_case.
