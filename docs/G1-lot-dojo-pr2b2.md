## 4. Choix déclarés (jamais silencieux)

1. **Entrées** : les corps admis (`Admission.tx` de `admit`) et les `NoQuorum` de PR-2b-1 ; les textes des K enregistrements `dojo-reading-v1` du premier jour lu, lus par `readRecord` (lecteur de PR-2, C-29 : jamais construits à la main). E_e = les `context_slot` des deux réponses acceptées de la **première lecture qui en porte deux** (D-3 l.227-228) ; les K textes sont attendus dans l'ordre i = 1..K, sinon `read_malformed` (contrat pour PR-2b-3) ; S_CUT = max E_e ; D_LAST = premier jour lu − 1, ≥ jour 1 sinon `read_malformed`. Les corps de slot > S_CUT sont ignorés (D-3 phase D) ; un corps admis à `err` non nul, ou dont le jour sort de [1, D_LAST + 1], arrête (`read_malformed`) ; (v) par `checkDays` et (iii) par `chainAccounts` de PR-2b-1 avant tout état ; **après G2** (ligne datée D-8), (v) porte aussi sur les couples (emplacement, `blockTime`) des corps sans quorum (§16.1).
2. **Reconstruction** : états par compte, emplacement par emplacement, dans l'ordre des emplacements ; repli de propriétaire identique à `chainAccounts` (entrée, puis `initializeAccount*` du corps côté post, puis dernier propriétaire, sinon `owner_unknown`) ; entrée post absente = 0 (compte fermé, mère C-1). Un `put(pre)` avant le `put(post)` révèle l'état à la sortie d'une fenêtre (no-op sinon). **Contrôle d'auto-cohérence** : l'état final égale, compte par compte, celui que rend `chainAccounts` (montant ; propriétaire si le montant est non nul), sinon `chain_break`.
3. **Valeur du jour** (D-7 l.348) : le solde de début de jour est pris au premier changement du solde de l'adresse dans le jour ; candidats : solde après chaque transaction (emplacement ordonné, ordre des rangs) ; pour un emplacement **non ordonné** (une transaction admise sans rang suffit, ensemble global de l'emplacement, comme `chainAccounts`), pour **toutes** les adresses touchées, L_s = B(avant s) + Σ_t min(δ(t), 0) et B(après s) (l.350) ; fin d'un compte dans l'emplacement = fin de l'unique chemin qui enchaîne (degrés ; un circuit finit où il commence, propriétaire du sommet gardé).
4. **L_s négatif** : la formule de D-7 l.350 peut rendre L_s < 0 (achat puis vente dans le même emplacement au-delà du solde d'avant) ; une valeur du jour négative n'est pas une ligne valide (mère D-2 : décimaux). Choix fail-closed : arrêt `bound_exceeded` (la borne des emplacements non ordonnés vaut 0, ligne datée Q-2 : tout emplacement non ordonné arrête déjà au contrôle (vii) du collecteur). Mesure sur la grille du test : 494 constructions arrêtées. Question Q-2 (alternatives chiffrées).
5. **Fenêtres** (D-6 l.340-343) : pour chaque compte d'un `NoQuorum` d'emplacements [lo, hi], la fenêtre court du jour de la lecture sans quorum (le plus petit `blockTime` des corps) au jour de la **première transaction admise sur le compte d'emplacement > hi**, inclus ; une transaction admise du même emplacement ne la ferme pas (fail-closed, cohérent avec le double affranchissement de `chainAccounts`, `h >= last && h <= slot`). Propriétaires rendus `null` sur la fenêtre : dernier propriétaire admis (état à l'entrée), propriétaires que les corps sans quorum nomment, propriétaires des entrées du compte dans les transactions admises de [lo, fermeture] (dont le pre révélé) : lecture de « tout propriétaire de a » (Q-7). **Corrigé après G2 (C-G2-1, Q-7 reprise, ligne datée D-6)** : le côté **post** de la transaction qui ferme la fenêtre, et toute transaction suivante de l'emplacement de fermeture ordonné, ne sont rendus `null` qu'au jour d1 ; l'annulation sur toute la fenêtre cachait une vente (§16.1). Arrêts `no_quorum_unbounded` : aucune transaction admise sur le compte après hi (fenêtre ouverte jusqu'à S_CUT), fenêtre ouverte à un E_e (lo ≤ E_e < fermeture), `NoQuorum` sans `blockTime` (Q-3) ; jours incohérents : `day_not_monotone`.
6. **(i) par jour** (D-8 l.365) : chaque jour 1..D_LAST, jours sans transaction compris, où aucun compte n'est dans une fenêtre à la fin du jour (d0 ≤ d < d1) : Σ des soldes = frappes − brûlages admis depuis 0 ; D_LAST non évaluable ⇒ `supply_mismatch`. **(ii)** (l.366) : après tous les emplacements ≤ E_e, pour chaque réponse : tout compte connu ici ou dans e, montant égal (absent de e = 0), propriétaire égal si le compte est dans e ; compte de e inconnu de la reconstruction ⇒ `enumeration_mismatch`.
7. **Lignes** (D-12 l.456-465) : `canonical({address, class, day, day_value})`, jours 1..D_LAST seulement (les transactions du premier jour lu ne servent qu'à (ii)) ; existence : `null`, ou > 0, ou dernière valeur définie avant > 0 (adresses nommées par une fenêtre sans jamais de solde comprises : lignes `null`) ; tri (jour, adresse en octets, `byteOrder`) ; octets = lignes + LF ; `sha256` des octets ; racine `rootOf` de PR-1a sur les lignes sans LF ; classe par `ownerClass`.
8. **`Eve` du premier jour lu** : `{addresses: adresses des lignes de D_LAST (ordre des octets), accounts: []}` (Q-5).
